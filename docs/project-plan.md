# WeRide — Project Plan

## 1. Purpose

WeRide is a semester-level mobile application prototype that enables university students to share rides and coordinate commuting.

## 2. Project Objectives

- Develop a simple and user-friendly mobile interface.
- Implement student authentication and profile management.
- Allow users to post and search for rides.
- Support ride booking and available-seat updates.
- Calculate shared travel costs.
- Demonstrate a basic SOS feature.

## 3. Project Components

### Component 1: UI/UX
Design the app screens, navigation layout, colors, typography, and reusable Flutter widgets.

### Component 2: UI Integration
Connect screens using Flutter navigation, buttons, forms, and input validation. Configure the app to run through VS Code.

### Component 3: Application Functionalities
Implement ride posting, searching, booking, cancellation, seat management, fare calculation, and simulated SOS.

### Component 4: Database
Configure Firebase Authentication and Cloud Firestore. Define the data structure and implement database operations.

## 4. Technology Stack

Flutter, Dart, Visual Studio Code, Firebase Authentication, Cloud Firestore, Git, GitHub, and Figma (planned).

## 5. Project Scope

The prototype includes authentication, student profiles, ride posting and searching, basic ride matching, bookings, fare calculation, and simulated SOS.

Advanced AI, live GPS tracking, in-app chat, professional drivers, smart scheduling, and real payment processing are excluded.

## 6. Three-Month Timeline

- Month 1: Requirements, UI design, project setup, and database planning.
- Month 2: Core features, authentication, and database integration.
- Month 3: Integration, testing, bug fixing, documentation, and demonstration.

## 7. Success Criteria

- Users can register and sign in.
- Drivers can post rides and students can search for them.
- Students can book available seats.
- Ride data is saved and retrieved through the database.
- Fare calculation and simulated SOS work as intended.
- The app can be demonstrated on an Android emulator or compatible device.

## 8. Limitations

This is an academic prototype. The SOS function does not contact real emergency services, and payment-method selection does not process real payments.
