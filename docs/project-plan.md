# WeRide — Project Plan

## 1. Project Overview
WeRide is a Flutter-based mobile application prototype that helps university students find and share rides, reduce commuting costs, and coordinate travel to university.

## 2. Project Objectives
- Provide student registration, login, and profile management.
- Allow students to post and search for rides.
- Support ride booking, cancellation, and seat availability updates.
- Calculate shared travel costs.
- Include a simulated SOS feature.

## 3. Main Components
1. UI/UX Design
2. UI Navigation and Integration
3. Application Functionalities
4. Database and Firebase Integration

## 4. Technology Stack
Flutter, Dart, Visual Studio Code, Firebase Authentication, Cloud Firestore, Git, GitHub, and Figma for planned UI design.

## 5. Project Scope
The prototype includes authentication, student profiles, ride posting and searching, basic ride matching, bookings, fare calculation, payment-method selection, and simulated SOS.

Advanced AI matching, live GPS tracking, in-app chat, professional drivers, smart scheduling, and real payment processing are excluded.

## 6. Three-Month Timeline
- Month 1: Requirements, UI design, project setup, and database planning.
- Month 2: Core features, authentication, and database integration.
- Month 3: Integration, testing, bug fixing, documentation, and demonstration.

## 7. Equal Team Division

### Member 1 — UI, Navigation, and Authentication
Responsible for screen design, reusable UI components, navigation, forms, input validation, login, signup, student profiles, and connecting authentication and profile screens to Firebase.

### Member 2 — Database, Ride Logic, and Booking
Responsible for the Firestore schema, database security rules, ride creation and search logic, basic matching, bookings, cancellations, seat updates, fare calculation, payment-method selection, and simulated SOS.

### Shared Responsibilities
Both members will contribute to integration, testing, GitHub collaboration, bug fixing, and the final demonstration and report. Workloads will be reviewed throughout development to maintain an approximately equal contribution.

## 8. Success Criteria
- Students can register, log in, and manage profiles.
- Users can post and search for rides.
- Students can book available seats and cancel bookings.
- Ride information can be saved and retrieved from the database.
- Fare calculation and simulated SOS work as intended.
- The app can be demonstrated on a compatible Android emulator or device.

## 9. Limitations
WeRide is an academic prototype. The SOS feature does not contact real emergency services, and payment-method selection does not process real payments.
